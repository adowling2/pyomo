Simulator interface audit and bug fixes
=======================================

30 October 2026. This audit extended work package A to the existing public
Simulator before the compile feature. Its results and source hashes are a
historical snapshot; current feature validation is recorded separately in
``results/compile_validation.json``.
Compatibility protects intended equations and results; it does not require
preserving an inaccurate trajectory, a crash, or unwanted caller mutation.

Scope and evidence
------------------

The new ``pyomo/dae/tests/test_simulator_interface.py`` contains 53 test
methods across the SciPy and CasADi backends, with additional subtests for
equation forms, grids, controls, and initialization. The tests use exact
solutions and an independent numerical reference rather than mocks or
snapshots generated by the implementation under test.

Coverage includes exponential and nonlinear scalar equations, coupled and
stiff ODEs, constant and zero derivatives, all advertised ODE integrators,
multi-indexed states, shifted time domains, asynchronous control changes,
explicit time dependence, linear and nonlinear index-one DAEs, repeated
calls, failure recovery, discretized-model initialization, input validation,
and preservation of values, fixity, scaling, and caller options.

An initial selective run against the unmodified Simulator produced 40 failed
checks, counting failed subtests. Invalid-grid and nonfinite-initial-state
tests were withheld from that run until validation was implemented, to avoid
sending invalid data into native integrators. Subsequent algebraic probes
exposed the branch and endpoint issues below. Full summaries and raw probe
observations are in ``results/interface_audit.json``.

Confirmed defects and corrections
---------------------------------

.. list-table:: Changes confined to the existing Simulator implementation
   :header-rows: 1
   :widths: 25 38 37

   * - Area
     - Observed problem
     - Correction
   * - Equation rearrangement
     - ``2*x + x_dot == 0`` drops the product term before x_dot. CasADi
       returns a constant trajectory; SciPy can raise TypeError.
     - Preserve non-derivative product terms when separating a sum.
   * - Constant derivatives
     - SciPy tries to call a numeric RHS, so even x_dot=2 fails.
     - Evaluate the RHS with Pyomo's value function.
   * - Input switches
     - SciPy retains cached derivatives/multistep history. For x_dot=u,
       with u=1 then 3 at t=.5, it returns x(1)=2 instead of 3 from x(0)=1.
     - Restart the integrator at each switch without changing the state.
   * - Nearly coincident times
     - A generated .30000000000000004 and an explicit .3 switch produce
       a tiny interval that can fail after restarting LSODA.
     - Snap output points to switch times within floating-point roundoff
       before taking their union. Keep exact switch coordinates.
   * - Final time
     - tstep=.3 on [0,1] stops at .9. initialize_model then clamps the
       final model value to the earlier sample.
     - Include the final time, with a shorter last interval if needed.
   * - Invalid grids and ICs
     - Empty/degenerate grids and nonfinite or incorrectly shaped states
       reach backend code or return inconsistent profile shapes.
     - Validate before calling an integrator.
   * - Input profile validation
     - Empty suffixes raise IndexError; missing initial keys and malformed
       profiles cause backend or dictionary errors.
     - Permit an empty suffix; validate each used profile and its initial key.
   * - Shifted input domains
     - CasADi uses profile[0], failing for inputs beginning at t=2.
     - Read the profile at the actual ContinuousSet lower bound.
   * - Physical time
     - CasADi cannot convert x_dot=t or an algebraic equation containing t.
     - Give the conversion walker a time expression. For normalized phases,
       use phase_start + duration*local_time in both ODE and algebraic rows.
   * - Caller options
     - CasADi inserts grid/output_t0/tf into caller dictionaries, including
       on failed calls.
     - Copy options before adding integration settings.
   * - Failed-call state
     - A failed call overwrites input/algebraic ordering while keeping the
       previous trajectory, making initialize_model unusable or inconsistent.
     - Validate with local ordering and restore prior ordering on solver failure.
   * - Algebraic initial guesses
     - With z**2=x, x_dot=z, x0=1 and model z0=1, the ignored guess can
       select z=-sqrt(x), yielding x(1)=.25 instead of 2.25.
     - Supply model algebraic values as guesses to IDAS, defaulting unset
       values to zero. Test both branches, inconsistent guesses, fixed x0,
       and segmented inputs.
   * - Algebraic output at switches
     - For z=x+u, the output at an input switch uses the preceding amplitude.
     - Recompute consistent algebraic output with the new amplitudes and
       fixed differential state. Reuse the existing normalized integrator
       with zero physical duration. Include final-time switches.

The public Simulator method signatures and two-array return convention
remain unchanged. Values assigned to algebraic variables are guesses, not
extra independent differential ICs. Reported algebraic values at control
switches now follow the right-hand input convention documented in the guide.
The audit itself introduced no sensitivity map, result class, dependency
workaround, or new adaptive integration algorithm.

Reference fixture correction
----------------------------

The existing SciPy piecewise pendulum fixture encoded the input-switch
defect. Its maximum profile error against an independent segmented DOP853
solve was ``0.0195036``. The corrected default-tolerance Simulator gives
``0.0000651`` on the same 102 points. The reference solves the explicit
two-state equations separately over [0,7], [7,15], and [15,20], with relative
tolerance ``1e-11`` and absolute tolerance ``1e-13``.

The SciPy fixture was updated after that comparison. A permanent regression
test also checks the example directly against the independent solve with
absolute tolerance ``1e-3``. The other existing Simulator fixtures remain
unchanged. Fixture hashes and the measured errors are retained in the audit
record.

Validation
----------

With both CasADi 3.8.1 and 3.8.2, the full ``pyomo/dae/tests`` suite reports
230 passed tests and 142 passed subtests. The environment uses Python
3.12.14, NumPy 2.5.4 and SciPy 1.18.1 on macOS ARM64, matching the dependency
baseline. Without NumPy, SciPy or CasADi, the original and new Simulator
modules complete 92 tests with 85 appropriate skips and seven passes.

Line coverage of ``simulator.py`` is 96%; all 96 modified executable lines
are covered. Black, typo checks, reStructuredText validation of these notes,
and whitespace checks pass. Commands and source hashes are recorded in
``results/interface_audit.json``. One coverage run emitted a Python
multiprocessing semaphore-cleanup warning at shutdown after all tests passed
with exit code zero; this is recorded separately from numerical test results.

To repeat the main checks in either dependency environment:

.. code-block:: sh

   python -m pytest pyomo/dae/tests -q
   python -m black --check pyomo/dae/simulator.py \
       pyomo/dae/tests/test_simulator_interface.py
   typos --config .github/workflows/typos.toml pyomo/dae/simulator.py \
       pyomo/dae/tests/test_simulator_interface.py

Remaining boundaries
--------------------

This is substantial public-interface coverage, not a proof for arbitrary
DAEs or every platform/dependency version. High-index and singular systems,
event-time derivatives, and higher-order sensitivities remain outside the
verified scope. Algebraic guesses can select a branch; they cannot guarantee
unique or globally consistent initialization for every nonlinear system.

The native CasADi sensitivity discrepancies recorded in the original matrix
remain dependency limitations. Correcting primal initialization and switch
outputs does not establish the correctness of DAE adjoints. The ODE-first
feature recommendation can be revised as that evidence improves. Existing
bugs are not a reason to duplicate paths or prohibit simpler feature designs.
